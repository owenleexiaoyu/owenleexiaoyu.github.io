1. 组里最近来了个新同学，我作为 Mentor，交流过程中能感受到长江后浪推前浪，我这前浪将要被拍在沙滩上了。新同学对技术有浓厚的兴趣，之前对 Android 甚至 React Native 都有了解和使用。和他的交流中，我有时在想，我那时候怎么做不到这样？我现在好像对有些东西还不如他了解。这些感受毫无疑问会滋生焦虑感，我要加油了，不能躺平呀，要将技术学好，坚持自己的学习计划。
2. 从上个月开始就一直在准备晋升的文档，和 Bob 反复对，反复改，都改出心理阴影了。不过这个过程中确实也思考了很多，比如如何处理和团队成员间的协作关系，如何去找 PM 要一些输入，如何想团队规划等等。还是挺有帮助的，不管晋升结果如何，这个经历都很宝贵。也不用太在意最后的结果，谋事在人成事在天。
3. 马上要开始写半年绩效，回顾这半年，我感觉我做的最不足的就是项目的进度跟进，以及和同事的协作上，有点陷入抢活的内耗中，整个人不太开心，有的时候也想或者干脆换个组，不想发生冲突，后来 Bob 说作为 Owner，要比其他同学有更深入的理解和思考，这个是最关键的。这点也让我稍微能从内耗中走出来一点，我决定做好自己的基本功：
    1. 整理领域知识和解决方案，成为领域专家
    2. 经常看代码（双端），了解和整理业务实现
    3. 深入 Android 领域，成为 Android 资深的研发
    4. 学习 iOS 知识，做些 iOS 需求
    5. 及时行动，不要拖
4. [2024.7.23] 今天和 Bob One/One，他向我介绍了一些他在绩效评定时的一些标准。听完有很有收获，同时也感到一些压力。
    1. 会看一位同学这个周期和上个周期的一个比较，如果和上个周期相比，没有一些新的突破，那不太可能保持高绩效。比如，去年是 M+，这个周期内的工作产出相比去年没有去年做不到的点，可能就会是 M，因为去年的表现提高了预期。
    2. 预期会随着调薪而逐渐变高，所以即使保持一贯的产出水平，也不意味着能持续获得高绩效。
    3. 所以要想持续保持好绩效，就得每个周期都有一些新的进步，做到之前做不到的事情，比如 Scope 更大，技术复杂度更高，项目推动做的更好，更有规划能力等等。
    4. 2-1 到 2-2 差不多能有 7 次绩效的安全期，超过 7 次绩效没有升上去，就会被 HR 拎出来，认为是没有潜力，可能就有被干掉的风险。
