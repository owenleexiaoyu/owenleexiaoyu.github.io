在使用 Obsidian 时，有两个功能是大家都一直想要折腾的，一个是 Publish，一个是 Sync。这两个功能都有官方付费插件，但大多数人会选择社区开源版本。

Publish 功能是将 Obsidian Vault 里的笔记发布成静态网站，我使用了 Obsidian Digital Garden 这个插件来实现，见 [[NightWrite/250516 将 Obsidian 笔记发布成博客\|250516 将 Obsidian 笔记发布成博客]]，并且自定义了一些功能，将博客和数字花园合二为一，见  [[NightWrite/260909 博客与数字花园融合第二期\|260909 博客与数字花园融合第二期]]。

Sync 功能则是在多台设备间实现笔记的同步，Obsidian 是本地笔记库，无需联网，但多台设备之间的笔记同步也是切实的需求。我的主要需求是实现家中的个人电脑与公司办公电脑之间的笔记同步。在 Obsidian 之前，我主要使用语雀来做笔记，它作为云端的笔记软件，能够实现全平台的笔记同步，体验是很不错的。后面切换到 Obsidian 后，我其实还一直保留着用语雀的习惯，就是需要它的同步功能，用来记录一些碎片内容和有用的网页链接等。后面这部分流程放到了幕布上，总体是稍微麻烦但够用，我会在幕布的今日速记里简单写写今天发生的琐事，方便后面在 Obsidian 里写日记时能够回想起今天发生了啥，别漏掉事情。也会把一些看到的有用的文章、网页贴到这里作为一个收藏的功能。这个收集的过程我觉得也是不够流畅的，之后我也会再做一些优化的尝试。但是还有一小块是空白的，就是当我想做一些笔记时，没有办法直接在我的知识库中做，这里的笔记不是说一些非正式的，零碎的随手记，而是比较认真在做某个知识的笔记。通过其他平台中转一遍总是觉得麻烦，因此我在公司和家里的流程总是割裂的状态。而知识库跨设备的同步就是将这个流程变得丝滑的关键所在。

但我迟迟没有进行同步的尝试，我也在网上搜索过相关的话题，了解了一些同步方案，官方的 Sync 是要收费的，每个月 8 美元，并且服务器是在国外，不是个很有性价比的方案。有人使用 Git + Github 来同步，这个方案其实是最简单稳定的，但每次都要像提交代码一样提交还是有点麻烦的。有人用 苹果的  iCloud 来做同步，适用于苹果全家桶，但听说 iCloud 对于这种文件很多的情况好像也有些小问题，我个人之前苹果设备上用 iCloud 的体验感受是我摸不清楚它同步的逻辑是什么，有的时候有的文件会莫名其妙冒出来，所以这个我也没有选择。还搜到坚果云开发了一个官方的同步插件，使用起来很方便，登陆一下就行了，我实际测试了一下，感觉速度稍微有点慢，并且在空间上有一些限制，所以这个也没有选择。还有 Remotely Save，据说配置起来比较麻烦，也略过了。总结来讲，之前社区里并没有见到综合来讲大家都极力推荐的、非常好用的同步插件。

直到在 Linux DO 社区里看到一篇 [帖子（Obsidian 同步插件推荐 - Fast Note Sync）](https://linux.do/t/topic/1518847/21)，我仔细看了一下后，觉得这个 [Fast Note Sync](https://github.com/haierkeys/obsidian-fast-note-sync) 插件挺不错，因为帖子里说了两个优点：一个是同步速度快、一个是配置简单，相对来说表现也是比较稳定的。但是这个插件需要在自己的服务器或 VPS、NSA 上部署一个程序，这点可能稍微麻烦点。帖子说的最推荐是在 VPS 或者 NAS 上部署，VPS 就是 Virtual Private Server，虚拟服务器，在一台大的物理服务器上利用虚拟化技术，分出多台独立的小服务器，每台就被称为 VPS。一般说的 VPS 都是说的海外的 VPS。我问了下 AI 国内有没有 VPS，也是有的，国内叫做轻量应用服务器，很多云厂商都有这个产品。我想了下，我正好可以买一台服务器用来部署这个，同时还能做一些其他的使用，对扩展自己的后端知识也是有帮助，所以在 AI 的推荐下，我在腾讯云上购买了一台香港节点的 Lighthouse 轻量服务器，2 核 CPU、2GB 内存、40GB SSD 存储，每个月 38 元，买了 3 个月。香港节点的优点在于不用备案了，这个可以省不少麻烦。

接下来写一下这个同步方案的配置过程。配置过程中，基本上是 AI 在指导流程并排查遇到的问题，所以这里我也只能简单写一下整体流程。

第一步是登陆购买的云服务器的终端，然后输入 FNS 提供的一键安装脚本进行安装，安装后执行命令来启动 FNS 服务，它会监听 9000 端口。通过 `http://服务器公网IP:9000` 来访问 FNS 的控制后台。这里遇到的第一个问题是，在浏览器里打开这个网址，显示 502，无法打开。这是因为腾讯云服务器有防火墙，9000 端口被防火墙拦住了。在服务器管理页面防火墙设置里将 9000 端口对自己电脑的 IP 放行。设置后还是没有通，但是通过下面的 CURL 命令是可以联通的，这是因为我电脑上开了 VPN，VPN 节点的 IP 不在白名单内，把 VPN 软件关了就走通了。在 VPN 软件中设置对 VPS 的 IP 直连，不走代理来解决。成功后能够打开 FNS 笔记控制台登陆页面。

```
curl --noproxy '*' -v --max-time 10 \
  http://服务器公网IP:9000/webgui/
```

注册一个账号，并作为 Admin 账号，就能登陆到控制台里。在控制台里可以先创建一个 Vault，也可以先生成一个访问令牌 Access Token。

第二步是在 Obsidian 中的社区插件市场中搜索 Fast Note Sync，下载插件并启用。在控制后台生成一个 Token，然后粘贴到插件的设置里，等插件显示 Service Connected 就可以了。这时候插件就会往我们部署的 FNS 服务上同步笔记了，这里的速度特别快，快到我震惊了，我 1000 篇左右的笔记，还有很多图片附件，几乎是秒传。去控制后台就能看到同步过来的 Vault 和里面所有的笔记了。可以直接在后台直接查看和编辑笔记，也会同步回本地的 Vault。

第三步是在另一台设备上先新建一个文件夹，然后用 Obsidian 打开这个文件夹，作为本地 Vault，然后同样安装 Fast Note Sync 插件。在这个设备浏览器里登陆控制后台，再给这个设备创建一个 Token，粘贴到插件里。连接上服务后，就开始对比本地和远端的 Diff，然后往本地同步笔记了。这里我失败了很多次，我笔记库里的图片比较多，所以经常超时，后面是把并发数量从默认的 20 个降低到 5 个，解决了这个问题。

其实过程真的挺简单，走完这三步，笔记就能够在设备间同步了，我测试了一下同步速度很快。但是如果出现一台设备在修改，一台设备把文件删了的情况，会出现删除的文件又会回来的问题。使用时还是要尽可能避免同时操作，以及完全离线使用，避免改动冲突。

后面我还在 AI 的建议下，增加了一层 HTTPS 反向代理，因为我正好也有自己的域名，使用了 Caddy 这个软件。这样就是通过 `https://notes.lixiaoyu.life`  来访问控制后台，而不是 `http://VPS公网IP:9000` 了。具体配置过程有点繁琐，我也是在 AI 的指导下才完成的，这里就不细说了。插件里的服务器地址也需要更新一下。

总而言之，现在我已经搭建好了 Fast Note Sync 服务，并且通过插件能够实现 Obsidian 笔记的多设备同步，一大难题终于被解决，以后不能再以不方便为由不努力做笔记了。
